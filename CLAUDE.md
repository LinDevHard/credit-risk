# CLAUDE.md — риск-сводка кредитного портфеля

## Стек
PostgreSQL 16 (Docker, контейнер `credit-risk-pg`, порт 5433, база `risk`) → схемы `raw` / `reporting` →
YAML-модель → Vega-Lite + vega-embed (статичный HTML). Python — только стандартная библиотека.

## Команды
- `./scripts/run.sh` — загрузить данные, пересоздать вьюхи, выгрузить JSON для дашборда
- `python3 -m unittest -v tests/test_metrics.py` — сверка цифр; запускать после любого изменения SQL
- `python3 scripts/build_specs.py` — пересобрать спеки дашборда
- `python3 -m http.server 8765 -d dashboard` — открыть дашборд

## Бизнес-определения (источник истины — задание, не менять без согласования)
- Портфель = Σ principal_outstanding × курс **на дату среза** (KZT = 1), без `written_off = 1`.
- PAR30 / PAR90 = доля портфеля с `days_past_due > 30` / `> 90` (строго больше).
- NPL = доля портфеля с `dpd > 90` ИЛИ `restructured = 1`.
- Провизии: NPL → 50% (приоритет), иначе dpd 31–90 → 10%, иначе 1%.
- Концентрация = доля топ-10 `group_id` (не borrower_id) в портфеле.
- Все доли считаются по сумме в тенге, не по числу кредитов.

## Правила
- SQL идемпотентный: `CREATE SCHEMA/TABLE IF NOT EXISTS`, `TRUNCATE` + `COPY`, `CREATE OR REPLACE VIEW`.
  Новые колонки во вьюхе добавлять только в конец (ограничение CREATE OR REPLACE VIEW).
- Не использовать INNER JOIN на курсы: пропуск курса должен быть виден в `v_data_quality`, а не тихо уменьшать портфель.
- Перед тем как писать вывод в README, проверять его запросом к `reporting.*` и не придумывать цифры.
- Аномалии данных фиксировать в README (раздел «Очистка данных»), а не исправлять молча.
- Дашборд: одна ось на график, 01.09 — серый, 01.10 — синий, проценты подписаны.

## Известные особенности данных
- 30 полных дублей на каждую дату.
- 23 кредита со списанием на 01.09 снова активны на 01.10.
- Курс 31.08 ≠ 01.09 — нельзя брать «последний доступный до даты».
- 438 кредитов с остатком после `maturity_date`.
